# Ирис

[![Проверка запуска и основных сценариев](https://github.com/tsenturion/iris/actions/workflows/check.yml/badge.svg)](https://github.com/tsenturion/iris/actions/workflows/check.yml)

Готовое локальное приложение на Python: определение вида ириса по измерениям, обработка CSV и журнал коллекции. Поддерживаются **Iris setosa, Iris versicolor и Iris virginica**. Набор Iris включён в проект; отдельное скачивание не требуется.

## Получение проекта

Установите [Python](https://www.python.org/downloads/) версии 3.11 или новее. При установке в Windows включите добавление Python в PATH. Проект проверен на Python 3.13. Для клонирования нужен [Git](https://git-scm.com/downloads); [uv](https://docs.astral.sh/uv/getting-started/installation/) ускоряет подготовку, но не обязателен.

Откройте PowerShell в папке для проектов:

```powershell
git clone https://github.com/tsenturion/iris.git
cd iris\iris-project
.\start.ps1
```

Если Git не установлен, на [странице репозитория](https://github.com/tsenturion/iris) выберите **Code → Download ZIP**, распакуйте архив и откройте PowerShell в каталоге `iris-project` внутри распакованной папки. Затем выполните `.\start.ps1`. После установки зависимостей и подготовки модели откройте <http://127.0.0.1:8501>.

При первой подготовке будут созданы пустой пользовательский журнал, три модели и отчёт сравнения. Справочные 150 цветов автоматически в журнал не добавляются. Для первой проверки введите измерения `5.1`, `3.5`, `1.4`, `0.2` см; ожидаемый результат — **Iris setosa**. Сохранение образца выполняется отдельной кнопкой.

## Запуск в Windows

Из папки проекта:

```powershell
.\start.ps1
```

Из корня репозитория:

```powershell
.\iris-project\start.ps1
```

Скрипт подготовит окружение, при первом запуске сравнит три классификатора и активирует рекомендованный по кросс-валидации. При последующих запусках он сохраняет вашу готовую активную модель. Откройте <http://127.0.0.1:8501>. Для остановки нажмите `Ctrl+C` в терминале.

Нужен установленный Python 3.11 или новее; при наличии `uv` используется `uv.lock`, иначе скрипт создаёт виртуальное окружение и устанавливает закреплённые версии из `requirements.txt`. При первой установке зависимостей нужен Интернет. После подготовки окружения приложение работает локально, без внешних сервисов. Доступ администратора не требуется.

Проверка запуска без открытия сервера:

```powershell
.\start.ps1 -Check
```

Ручной запуск с `uv`:

```powershell
uv sync --locked --no-python-downloads
uv run --locked python -X utf8 -m iris_journal prepare
uv run --locked streamlit run app.py
```

Ручные команды установки, обучения и проверки из этого README выполняются внутри `iris-project`. В корне репозитория также находятся презентации, дополнительные материалы и расписание; обзор — в [главном README](../README.md).

Общий ручной запуск без `uv`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 -m iris_journal prepare
.\.venv\Scripts\python.exe -m streamlit run app.py
```

В Linux и macOS используйте `python3` для создания окружения и `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`. PowerShell-скрипт предназначен для Windows; автоматическая проверка выполняется на Windows с Python 3.13.

## Определение нового ириса

1. В разделе «Определить вид» откройте вкладку «Один цветок».
2. Введите длину и ширину чашелистика, длину и ширину лепестка **одного цветка в сантиметрах**.
3. Нажмите «Определить вид». Приложение покажет предполагаемый вид, оценки всех трёх классов, использованные измерения и модель.
4. При необходимости задайте номер, дату, место и заметки и нажмите «Сохранить образец и прогноз».
5. Откройте образец в «Журнале». Здесь можно уточнить наблюдения, указать предположение человека или подтвердить вид с независимым основанием.

Модель применяет сохранённый конвейер без нового обучения. Измерения за пределами справочного диапазона не блокируются, но приложение предлагает проверить значения и единицы. Оценки модели не являются подтверждением вида и не означают, что цветок обязательно принадлежит одному из трёх поддерживаемых видов.

## Пакетная обработка CSV

Во вкладке «CSV с образцами» скачайте шаблон либо используйте [пример](examples/measurements.csv). Загрузите файл, нажмите «Проверить CSV и определить виды», просмотрите результат и скачайте его или добавьте весь набор в журнал.

Обязательные столбцы:

| Столбец | Измерение |
| --- | --- |
| `sepal_length_cm` | Длина чашелистика, см |
| `sepal_width_cm` | Ширина чашелистика, см |
| `petal_length_cm` | Длина лепестка, см |
| `petal_width_cm` | Ширина лепестка, см |

Дополнительные столбцы: `sample_code`, `observed_on`, `location`, `notes`. Дата — `ГГГГ-ММ-ДД`; пустая дата заменяется текущей датой по Екатеринбургу. Если номера не указаны, создаются номера с общим префиксом загрузки.

Поддерживаются UTF-8 с BOM или без него и Windows-1251; разделители — запятая, точка с запятой или табуляция. Для десятичной запятой используйте точку с запятой или табуляцию как разделитель либо заключайте число в кавычки. Допускается до 5000 строк и 2 МБ.

Файл проверяется целиком до получения прогнозов. Пропущенные, лишние или повторяющиеся столбцы, неверные значения, даты и повторные номера отклоняются; ошибки строк показываются с номерами. Только после успешной проверки используется одна активная модель для всего набора. Просмотр и скачивание результатов не добавляют записи в журнал.

Сохранение набора выполняется одной транзакцией: конфликт номера с журналом или ошибка записи отменяет весь набор. Повторяющиеся номера сравниваются без учёта регистра, включая кириллицу. Готовые результаты и экспорт журнала содержат дополнительные служебные столбцы; для нового входного файла используйте формат шаблона.

## Журнал и сводка

- Поиск по номеру и месту, фильтр по статусу определения человеком, редактирование и CSV выбранных записей.
- Предположение человека, его обоснование, подтверждённый вид и основание подтверждения хранятся отдельно от прогноза.
- Каждая правка создаёт неизменяемую редакцию. При одновременном редактировании устаревшая форма не перезаписывает новую запись.
- Прогноз содержит модель, алгоритм, время, оценки классов, исходные измерения и редакцию образца.
- После правки записи прежний прогноз сохраняется и отмечается как относящийся к другой редакции. Для актуального результата нажмите «Определить вид этого образца».
- При совпадении редакции отображается сопоставление прогноза с подтверждённым человеком видом.
- Сводка показывает состав коллекции, статистику измерений, актуальные прогнозы и совпадения с подтверждениями.
- Экспорт CSV сохраняет человеческие определения и машинные результаты в разных столбцах; потенциальные формулы в текстовых ячейках экранируются.

## Обучение и сравнение моделей

Раздел «Модель» позволяет обучить базовую логистическую регрессию и посмотреть активную модель, подробную оценку и историю обучения. В разделе «Сравнение моделей» доступны три классификатора: логистическая регрессия, ближайшие соседи и дерево решений.

Iris делится на **120 обучающих и 30 тестовых образцов** с сохранением пропорций видов и `random_state=42`. Для всех алгоритмов используется одно разбиение. Масштабирование входит в конвейер и обучается только на обучающей части; дерево работает без масштабирования.

Небольшие сетки параметров проверяются по среднему F1 трёх классов на пяти стратифицированных разбиениях обучающей части. Рекомендация определяется до оценки тестовых данных. Итоговый отчёт содержит accuracy, precision, recall, F1, матрицу ошибок, показатели по видам, ошибочные определения и использованные параметры.

Сравнение сохраняет все модели и отчёт, сохраняя текущую активную модель. Для смены выберите классификатор и нажмите «Использовать выбранную модель». Отчёт можно скачать в JSON. Каждое обучение создаёт самостоятельную версию; ошибка подготовки новой модели не меняет прежний активный указатель.

Во вкладке «Группировка» K-means разделяет справочные измерения на три группы без использования видов при обучении. Доступны диаграмма, состав групп, центры в сантиметрах, силуэт, ARI, сохранение отчёта и экспорт CSV. Номер группы не является видом растения; группировка не становится активным классификатором.

## Команды

Из папки проекта:

```powershell
uv run --locked python -X utf8 -m iris_journal prepare
uv run --locked python -X utf8 -m iris_journal model
uv run --locked python -X utf8 -m iris_journal train
uv run --locked python -X utf8 -m iris_journal compare
uv run --locked python -X utf8 -m iris_journal compare --activate-recommended
uv run --locked python -X utf8 -m iris_journal cluster
uv run --locked python -X utf8 -m iris_journal predict IR-001
uv run --locked python -X utf8 -m iris_journal predict-csv examples/measurements.csv --output results.csv
```

`predict` работает с сохранённым номером и сохраняет отдельный прогноз. `predict-csv` записывает результаты в новый CSV без добавления в журнал; существующий файл не перезаписывается. Без `uv` замените `uv run --locked python` на `.\.venv\Scripts\python.exe`.

## Данные и резервная копия

| Путь | Содержимое |
| --- | --- |
| `data/journal.sqlite3` | Журнал, редакции наблюдений и прогнозы |
| `data/datasets/Iris.source.csv` | Исходный скачанный CSV |
| `data/datasets/iris.csv` | Нормализованные 150 образцов |
| `data/datasets/source.json` | Источник и описание преобразования |
| `data/artifacts/models/<идентификатор>/` | Конвейер и описание модели |
| `data/artifacts/active_model.json` | Указатель активной модели |
| `data/artifacts/experiments/` | Отчёты сравнения и группировки |
| `logs/iris-ГГГГ-ММ-ДД.log` | Диагностика с хранением до 30 дней |

В «Журнале» откройте «Резервная копия журнала», создайте актуальную копию и скачайте SQLite-файл. Копия согласована даже при работающем приложении и содержит все записи, редакции и прогнозы. Модели и справочный набор в неё не входят; для полного переноса сохраните также `data/artifacts` и `data/datasets`.

Для восстановления остановите приложение. Перенесите текущую базу и возможные файлы `journal.sqlite3-wal`, `journal.sqlite3-shm` в отдельную папку. Поместите скачанную копию в `data/journal.sqlite3` и запустите приложение. Старые WAL/SHM-файлы не должны оставаться рядом с восстановленной базой.

Пользовательская база, модели и логи исключены из Git; справочный набор включён в проект. Пути можно изменить переменными `IRIS_DATA_DIR` и `IRIS_LOG_DIR`. Время в логах — UTC; даты и время в интерфейсе — Екатеринбург.

Пример отдельного размещения пользовательских данных в PowerShell перед запуском:

```powershell
$env:IRIS_DATA_DIR = 'C:\iris-data'
$env:IRIS_LOG_DIR = 'C:\iris-logs'
.\start.ps1
```

При таком размещении скопируйте папку `data\datasets` в `C:\iris-data\datasets` до первого обучения. Уже подготовленная модель и база по прежнему пути автоматически не переносятся; при переносе коллекции следуйте процедуре резервного копирования выше.

## Решение частых проблем

| Проблема | Что сделать |
| --- | --- |
| Скрипт заблокирован политикой PowerShell | Запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1`. Параметр действует только на этот процесс и не меняет постоянную политику компьютера. Если ограничение задано организацией, используйте ручной запуск Python. |
| `python`, `py` или `uv` не найден | Установите Python, включите PATH и откройте новый терминал. Для проверки выполните `python --version` или `py -3 --version`. |
| Не удалось установить зависимости | Проверьте доступ к индексу Python-пакетов и сообщения терминала. Повторите `.\start.ps1 -Check`; подробности работы приложения сохраняются в `logs`. |
| Порт 8501 занят | Остановите прежний экземпляр или после `.\start.ps1 -Check` выполните `.\.venv\Scripts\python.exe -m streamlit run app.py --server.port 8502`. Откройте соответствующий адрес. |
| Набор Iris не найден | Восстановите `data/datasets/iris.csv` из репозитория. Если задан `IRIS_DATA_DIR`, проверьте папку `datasets` внутри выбранного каталога. |
| Версии среды изменились или конвейер повреждён | Выполните `.\start.ps1 -Check`: подготовка создаст совместимую активную модель на локальном Iris. Можно также обучить её в интерфейсе. |
| Номер образца уже существует | Откройте существующую запись для правки или задайте новый номер. При конфликте CSV весь пакет остаётся несохранённым. |
| Прогноз помечен прежней редакцией | Откройте образец и выполните «Определить вид этого образца». История предыдущих результатов сохранится. |

```powershell
git pull --ff-only

```

Если вы изменяли исходный код, сначала сохраните свои изменения в отдельной ветке или коммите. Для копии из ZIP скачайте новый архив и перенесите пользовательскую базу по процедуре восстановления. Готовые конвейеры привязаны к версиям среды: если они изменились, новая модель подготавливается автоматически.

## Источник и область применения

Источник: [scikit-learn/iris на Hugging Face](https://huggingface.co/datasets/scikit-learn/iris). В наборе 150 записей, по 50 каждого вида. Названия столбцов нормализованы, префикс `Iris-` у видов удалён; исходные измерения сохранены. `source_id` служит идентификатором строки и не входит в признаки.

Карточка источника указывает **CC0-1.0**. Описание включённых файлов, происхождения и преобразования приведено в [data/datasets/README.md](data/datasets/README.md).

Пользовательские наблюдения не изменяют справочный набор и не включаются в обучение автоматически. Доля верных определений в карточке модели относится к 30 выделенным тестовым образцам Iris. Для работы с конкретной коллекцией качество следует проверить на её независимых измерениях.

Загружаются локальные модели, созданные приложением. Версии среды сверяются с описанием модели; при изменении зависимостей потребуется повторное обучение. Не подменяйте файлы конвейера внешними моделями.

## Целевая проверка завершённого кейса

```powershell
uv run --locked python -X utf8 -m unittest tests.test_module6 tests.test_module1.JournalTests.test_export_preserves_russian_text_and_separate_labels tests.test_module1.JournalTests.test_export_escapes_spreadsheet_formulas tests.test_module1.JournalTests.test_stale_edit_does_not_overwrite_new_revision tests.test_ui.InterfaceTests.test_create_edit_history_and_summary tests.test_module2.ModelTests.test_reload_does_not_train_again_and_preserves_predictions -v
```

Проверяются обработка CSV, пакетное применение без обучения, атомарное сохранение, конфликт номеров, сохранность редакций, экспорт, резервная копия, подготовка модели, команды и полный сценарий интерфейса. Тесты используют временные папки и не изменяют пользовательский журнал.

На GitHub [автоматическая проверка](https://github.com/tsenturion/iris/actions/workflows/check.yml) устанавливает закреплённые зависимости, проверяет подготовку из свежей копии и запускает три ключевых сценария: отдельный цветок, пакет CSV и восстановление резервной копии. Изменения только Markdown и лицензии не запускают её повторно.

Исходный код и документация проекта доступны по [лицензии MIT](LICENSE), текст приведён на русском языке. Справочные CSV распространяются с указанием источника под CC0-1.0; лицензии установленных зависимостей остаются их собственными.
