# Работа со своей копией и участие в проекте

## Подготовка

Создайте fork на GitHub для собственных изменений или клонируйте репозиторий для локальной работы. В своей копии выполните команды из [README](README.md), затем создайте отдельную ветку:

```powershell
git switch -c my-change
```

Начните с [описания архитектуры](docs/architecture.md) и навигации по коду в README. Справочный Iris включён в репозиторий; личная база и модели создаются локально.

## Правила изменений

- Сохраняйте порядок четырёх признаков и единицу измерения — сантиметр.
- Разделяйте пользовательские наблюдения, предположения, подтверждения и прогнозы модели.
- Выполняйте подбор параметров только на обучающей части; итоговый тест служит независимой оценкой.
- Создавайте поясняющие docstring для модулей, классов и функций на русском языке. Сложные решения объясняйте комментариями `#`.
- Обновляйте README, если меняются запуск, формат данных, команды или пользовательские сценарии.
- Проверяйте затронутые сценарии. Проверки хранения и интерфейса должны использовать временные данные.

Для запуска отдельной проверки используйте её полное имя, например:

```powershell
uv run --locked python -X utf8 -m unittest tests.test_module6.ApplicationTests.test_conflict_rolls_back_every_new_sample_and_prediction -v
```

При изменении зависимостей согласованно обновляйте `pyproject.toml`, `uv.lock` и `requirements.txt`. Для экспорта закреплённых зависимостей:

```powershell
uv lock
uv export --locked --format requirements.txt --no-hashes --no-dev --no-emit-project --no-header --no-annotate --output-file requirements.txt
```

## Предложение изменений

В коммите и описании pull request на русском языке укажите, какая проблема решена, какое поведение получилось и какие проверки выполнены. Небольшое изменение должно решать одну понятную задачу.

Перед отправкой просмотрите `git diff --cached --stat` и список добавленных файлов. Пользовательская база, выгруженные наблюдения, модели, логи, окружение и секреты остаются локальными; соответствующие пути уже исключены в `.gitignore`.

При сообщении об ошибке в [Issues](https://github.com/tsenturion/iris/issues) укажите версии Python и ОС, шаги воспроизведения, ожидаемый и фактический результат. Прикладывайте только относящийся к сбою фрагмент лога после удаления личных сведений.
